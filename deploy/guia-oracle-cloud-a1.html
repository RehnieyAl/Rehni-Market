    Desplegar RehniMarket en Oracle Cloud con Ampere A1

    Guía paso a paso para llevar el stack (Caddy, FastAPI, PgBouncer, PostgreSQL y MinIO) a una VM ARM gratuita de Oracle Cloud, con HTTPS de Let's Encrypt en y api.. Usa el mismo docker-compose.yml y caddy/Caddyfile que en desarrollo: solo cambian los .env.

    Tus datos — los comandos de la guía se rellenan solos (se guardan en este navegador)

    Antes de empezar

    Compatibilidad del proyecto con ARM64, comprobada el 06/11/2026:

    PiezaEstado en ARM64
    Imágenes: caddy:2.11-alpine, postgres:17-alpine, edoburu/pgbouncer, MinIO de Chainguard (digest fijado), python:3.13-slim, node:22-alpine, uv✅ Todas publican linux/arm64
    Dependencias Python (uv.lock)✅ Todas con paquete aarch64 para Python 3.13: el build no necesita compilador
    Correo (smtp.gmail.com:587)✅ Oracle bloquea el 25, no el 587. Si tu red bloquea otro puerto: paso «Correo SMTP»
    Usa 4 OCPU. docker-compose.yml limita el backend a cpus: "4" (y Postgres a 3). Con menos OCPU, Docker se niega a crear el contenedor. 4 OCPU / 24 GB es justo el máximo gratuito de A1.

    Necesitas: una cuenta de Oracle Cloud, un dominio propio con acceso a su DNS, una clave SSH (se crea en el paso siguiente) y acceso al repositorio de GitHub.

    Clave SSH en tu PC

    Oracle no usa contraseña para entrar al servidor: pide tu clave pública al crear la VM y solo deja entrar a quien tenga la clave privada correspondiente. Por eso la clave se crea antes de la VM. Todo esto, en tu equipo (funciona igual en fish y en bash):

    # Clave dedicada al servidor (ed25519). Pide una passphrase: ponla, protege la clave si te roban el PC
ssh-keygen -t ed25519 -C "rehnimarket-oci" -f ~/.ssh/rehni_oci

ls -l ~/.ssh/rehni_oci*
# rehni_oci      ← PRIVADA: nunca sale de tu equipo (permisos -rw-------)
# rehni_oci.pub  ← PÚBLICA: la que pegas en Oracle

cat ~/.ssh/rehni_oci.pub    # copia esta línea completa (ssh-ed25519 AAAA… rehnimarket-oci)

    Para no escribir la passphrase en cada conexión, cárgala una vez por sesión en el agente:

    ssh-add ~/.ssh/rehni_oci
    Alternativa: que Oracle genere la clave. En «Add SSH keys» → Generate a key pair for me → Save private key. Luego muévela y protégela: mv ~/Descargas/ssh-key-*.key ~/.ssh/rehni_oci && chmod 600 ~/.ssh/rehni_oci. Oracle no la guarda: si no la descargas en ese momento, se pierde.
    Haz copia de la clave privada (gestor de contraseñas o USB cifrado). Si la pierdes no hay «recuperar contraseña»: habría que desmontar el disco de arranque de la VM, montarlo en otra instancia y editar authorized_keys a mano.

    Crear la VM

    En la consola: Compute → Instances → Create instance.

    CampoValor
    ImageCanonical Ubuntu 24.04 (aarch64): el SO de producción de la ficha técnica
    ShapeAmpere → VM.Standard.A1.Flex · 4 OCPU · 24 GB
    NetworkingVCN con subred pública · «Assign a public IPv4 address»
    Add SSH keysPaste public keys → pega el contenido de ~/.ssh/rehni_oci.pub (paso anterior)
    Boot volume100–200 GB (hasta 200 GB en total es gratuito)
    «Out of host capacity» Es habitual en A1. Prueba otro Availability Domain o reintenta más tarde. Pasar la cuenta a Pay As You Go suele resolverlo, y no se cobra mientras no superes los límites gratuitos.

    IP pública reservada

    Networking → IP management → Reserved public IPs → Reserve. Luego, en la instancia: Attached VNICs → VNIC → IPv4 Addresses → Edit: quita la IP efímera («No public IP») y asigna la reservada. Así la IP no cambia si la VM se reinicia.

    Conectarte por SSH desde tu PC

    a) Atajo en ~/.ssh/config

    Con esto basta escribir ssh rehni-oci: no hay que recordar la IP, el usuario ni la clave. Ábrelo con nano ~/.ssh/config y añade al final:

    Host rehni-oci 
    HostName 
    User 
    IdentityFile ~/.ssh/rehni_oci
    IdentitiesOnly yes
    ServerAliveInterval 60
    chmod 700 ~/.ssh
chmod 600 ~/.ssh/config ~/.ssh/rehni_oci

    El usuario depende de la imagen: ubuntu en Ubuntu (esta guía), opc en Oracle Linux. ServerAliveInterval evita que la sesión se corte si la dejas quieta.

    b) Primera conexión

    ssh rehni-oci

    La primera vez pregunta «Are you sure you want to continue connecting (yes/no)?»: escribe yes. SSH guarda la huella del servidor en ~/.ssh/known_hosts y en adelante avisará si cambia (posible suplantación). Dentro del servidor, comprueba:

    whoami     # ubuntu
uname -m   # aarch64
exit       # vuelve a tu PC

    c) Copiar archivos entre tu PC y el servidor

    # Desde tu PC (ejemplo: subir el .env del backend, que no va por Git)
scp RehniMarket-backend/.env rehni-oci:Rehni-Market/RehniMarket-backend/.env

# Carpetas completas (solo envía lo que cambió)
rsync -avz backups/ rehni-oci:Rehni-Market/backups/

# Del servidor a tu PC
scp rehni-oci:Rehni-Market/backups/backup.log .

    d) Si no conecta

    ErrorCausa y solución
    Connection timed outEl 22 no está abierto para tu IP en la Security List (paso «Abrir puertos»), tu IP pública cambió (consúltala con curl -s ifconfig.me), o la VM no tiene IP pública.
    Permission denied (publickey)Usuario equivocado (ubuntu vs opc), clave distinta de la que pegaste en Oracle, o permisos: chmod 600 ~/.ssh/rehni_oci. Detalle: ssh -v rehni-oci.
    UNPROTECTED PRIVATE KEY FILELa clave es legible por otros: chmod 600 ~/.ssh/rehni_oci.
    REMOTE HOST IDENTIFICATION HAS CHANGEDSi recreaste la VM con la misma IP es normal: ssh-keygen -R y vuelve a conectar. Si no la recreaste, no continúes: alguien podría estar suplantando el servidor.
    Pide contraseñaNo está usando la clave: revisa IdentityFile y que escribiste ssh rehni-oci (no otro nombre).

    e) Seguridad del acceso

    Las imágenes de Oracle ya traen desactivado el acceso con contraseña. Compruébalo en el servidor:

    sudo sshd -T | grep -E 'passwordauthentication|permitrootlogin'
# passwordauthentication no
# permitrootlogin without-password (o no)

    Para dar acceso a otra persona, añade su clave pública (una línea) al final de ~/.ssh/authorized_keys en el servidor. Nunca compartas tu clave privada.

    Opcional: con la extensión Remote - SSH de VS Code, el host rehni-oci aparece directamente para editar archivos del servidor.

    Abrir puertos (dos capas)

    a) Security List de la VCN

    Networking → Virtual cloud networks → tu VCN → Security Lists → Default → Add Ingress Rules:

    Source CIDRProtocoloPuertoPara qué
    0.0.0.0/0TCP80Validación de Let's Encrypt y redirección a HTTPS
    0.0.0.0/0TCP443HTTPS
    0.0.0.0/0UDP443HTTP/3 (opcional)
    /32TCP22SSH: ya existe abierta a todos; mejor limitarla a tu IP (curl -s ifconfig.me). Si tu IP cambia, actualiza esta regla o no podrás entrar
    No abras el 8000 ni el 5433. La API directa y PostgreSQL solo escuchan en 127.0.0.1 del servidor.

    b) iptables dentro de la VM

    Las imágenes Ubuntu de Oracle traen reglas que rechazan todo salvo el 22. Ábrelos una vez conectado:

    ssh rehni-oci

sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo iptables -I INPUT 6 -p udp --dport 443 -j ACCEPT
sudo netfilter-persistent save

    DNS del dominio

    En el panel de tu proveedor de dominio, dos registros hacia la IP reservada:

    TipoNombreValorTTL
    A (o @)300 al principio; 3600 cuando esté estable
    Aapiigual

    Comprueba desde tu equipo que los dos responden con la IP:

    dig +short 
dig +short api.
    No levantes Caddy antes de que resuelvan los dos. Let's Encrypt fallaría la validación y, tras varios fallos, limita temporalmente los intentos.

    Correo SMTP y puertos bloqueados

    RehniMarket envía correos (códigos de verificación, recuperar contraseña, pedidos, devoluciones…) conectándose a un servidor SMTP. Muchos proveedores de nube y redes bloquean puertos de correo para frenar el spam, así que conviene saber cuáles quedan abiertos y cómo cambiar si uno falla.

    a) Qué puertos existen y cuáles bloquea Oracle

    PuertoUsoOracle CloudCifrado (SMTP_SECURITY)
    25Entre servidores de correo (no para enviar desde una app)❌ Bloqueado de salida en todas las cuentas—
    587Envío autenticado (el estándar). El que usa RehniMarket por defecto✅ Abiertostarttls
    465Envío autenticado con TLS desde el inicio✅ Abiertossl
    2525Puerto alternativo de relays (Brevo, SendGrid, Mailgun…). Casi nunca está bloqueado✅ Abiertostarttls

    En Oracle, además, la Security List trae una regla de salida «All protocols → 0.0.0.0/0» y la VM no filtra la salida con iptables. Si borraste esa regla de egress, vuelve a crearla o el servidor no podrá conectarse a nada.

    Quien suele bloquear el 587 no es Oracle, sino la red. Wi-Fi institucionales (universidad, SENA, empresa) y algunos operadores bloquean el 587 y el 465. Por eso en tu PC puede fallar el correo y en el servidor funcionar, o al revés.

    b) Diagnóstico: ¿qué puertos deja salir esta red?

    Desde el contenedor del backend (en el servidor o en tu PC; prueba la red real por la que sale el correo):

    docker compose exec -T backend python3 - <<'EOF'
import socket
for host, port in [("smtp.gmail.com", 25), ("smtp.gmail.com", 587),
                   ("smtp.gmail.com", 465), ("smtp-relay.brevo.com", 2525)]:
    try:
        socket.create_connection((host, port), 5).close(); r = "ABIERTO"
    except Exception as e:
        r = f"bloqueado ({type(e).__name__})"
    print(f"{host}:{port} -> {r}")
EOF

    Resultado esperado en Oracle Cloud: 25 → bloqueado, 587, 465 y 2525 → ABIERTO. Este bloque usa sintaxis de bash: en el servidor (Ubuntu) funciona tal cual.

    Y en los logs, un envío fallido aparece así:

    docker compose logs backend | grep -iA3 "error al enviar correo"
# TimeoutError / ConnectionRefusedError → puerto bloqueado (soluciones B o C)
# SMTPAuthenticationError               → usuario/contraseña (contraseña de aplicación de Google)

    c) Soluciones (solo cambiando RehniMarket-backend/.env)

    El servidor, el puerto y el cifrado se configuran con variables. Sin definirlas, todo sigue como siempre (Gmail por 587). Tras cambiarlas: docker compose up -d backend.

    A · Gmail por 587 (por defecto, funciona en Oracle): no hay que añadir nada.

    GMAIL_USERNAME="notificaciones@"
GMAIL_APP_PASSWORD="contraseña de aplicación de Google"

    B · Gmail por 465 (si una red bloquea el 587 pero no el 465):

    SMTP_PORT=465            # SMTP_SECURITY=ssl se deduce solo con el 465

    C · Relay por 2525 (si están bloqueados el 587 y el 465, o necesitas más volumen). Ejemplo con Brevo (plan gratuito): crea la cuenta, verifica el remitente o tu dominio y copia las credenciales de SMTP & API → SMTP:

    SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=2525
SMTP_SECURITY=starttls
SMTP_USERNAME="usuario SMTP de Brevo"
SMTP_PASSWORD="clave SMTP de Brevo"
EMAIL_FROM="notificaciones@"   # remitente verificado en Brevo

    Funciona igual con SendGrid o Mailgun (cambian host y credenciales) o con OCI Email Delivery de Oracle (smtp.email.<región>.oci.oraclecloud.com, puerto 587, credenciales SMTP del usuario de OCI y remitente aprobado en la consola).

    VariablePor defectoPara qué
    SMTP_HOSTsmtp.gmail.comServidor SMTP
    SMTP_PORT587Puerto
    SMTP_SECURITYstarttls (ssl si el puerto es 465)Cómo se cifra la conexión
    SMTP_USERNAME / SMTP_PASSWORDGMAIL_USERNAME / GMAIL_APP_PASSWORDCredenciales del servidor SMTP
    EMAIL_FROMSMTP_USERNAMERemitente visible; obligatorio cuando el usuario SMTP no es una dirección de correo
    Que el correo no acabe en spam. Si envías como @, añade en el DNS los registros SPF y DKIM que te indique el proveedor (Google Workspace, Brevo, OCI…). Una cuenta de Gmail gratuita limita el envío a unos 500 correos al día.
